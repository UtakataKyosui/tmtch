# `tmrch` 仕様書

## 目的

`tmrch` は `touch` のようにファイルを作成する CLI である。ファイル名の拡張子に対応するテンプレートが登録されている場合は、その内容を書き込んで新規ファイルを作成する。テンプレートの編集は CLI 内で行わず、利用者が設定した既存のエディタ（例: VS Code）を起動して行う。

この仕様では、ユーザーの依頼に合わせてコマンド名を `tmrch` とする。現時点の Cargo パッケージ名は `tmtch` であるため、実装時にバイナリ名・設定ディレクトリ名をどちらに統一するかを決め、原則として `tmrch` にそろえる。

## 想定する利用例

```console
$ tmrch app.rs
# `rs` 用テンプレートを使って ./app.rs を作成

$ tmrch README.md
# `md` 用テンプレートを使って ./README.md を作成

$ tmrch --edit rs
# Rust 用テンプレートを既定エディタで開く

$ tmrch --list
# 登録済みテンプレートを一覧表示
```

## コマンド仕様

### ファイル作成: `tmrch <FILE>`

- 引数には作成するファイルパスを 1 つ指定する。
- 対象が存在しない場合、親ディレクトリがすでに存在することを前提に、新しいファイルを作成する。
- 拡張子を取得し、対応するテンプレートがあればその内容を UTF-8 テキストとして書き込む。
- 対応テンプレートがなければ、空ファイルを作成する。これは `touch` の代替として最低限期待される動作である。
- 対象がすでに存在する場合は、内容を上書きしない。終了ステータスを失敗にし、対象が存在する旨を標準エラーに表示する。
- 引数がディレクトリを指す場合、または書き込みに失敗した場合も失敗として扱う。
- 拡張子のないファイル（`Makefile`、`README` など）は、初期版では空ファイルとして作成する。名前ベースのテンプレート対応は将来拡張とする。

拡張子の解釈は、末尾の拡張子を小文字化した値とする。たとえば `Main.RS` は `rs` として扱う。`.gitignore` のように先頭のドットしかない名前は「拡張子なし」と扱う。

### テンプレート編集: `tmrch --edit <EXTENSION>`

- `<EXTENSION>` は `rs` または `.rs` のように指定でき、内部では先頭のドットを除いた小文字のキーに正規化する。
- 登録済みテンプレートなら、そのテンプレートファイルをエディタで開く。
- 未登録の場合は空のテンプレートファイルを作成してエディタで開く。保存して空のままでもテンプレートとして登録される。
- エディタの終了コードが 0 以外の場合は失敗として扱う。
- エディタ起動後に CLI が終了すると、利用者が保存完了する前に処理が終わるため、初期版ではエディタプロセスの終了を待機する。

### 一覧表示: `tmrch --list`

- 登録済みテンプレートを拡張子の昇順で標準出力に表示する。
- 出力は、スクリプトでも扱いやすい 1 行 1 拡張子の形式とする。

```text
md    /Users/alice/.config/tmrch/templates/md
rs    /Users/alice/.config/tmrch/templates/rs
```

- テンプレート本文は表示しない。本文を誤って端末ログに残さず、長いテンプレートでも一覧を読みやすくするためである。
- テンプレートがない場合は何も出力せず、成功として終了する。

## 設定と保存先

テンプレート本文を設定ファイルへ埋め込むのではなく、拡張子ごとに独立したテンプレートファイルとして保持する。これにより、VS Code などの通常のエディタでそのまま開いて編集できる。

初期案の保存先は OS のユーザー設定ディレクトリ配下とする。

```text
<config-dir>/tmrch/
├── config.toml
└── templates/
    ├── rs
    ├── md
    └── py
```

- macOS: `~/Library/Application Support/tmrch/`
- Linux: `~/.config/tmrch/`（`XDG_CONFIG_HOME` があればその配下）
- Windows: OS が返す設定ディレクトリ配下

`config.toml` には、少なくともエディタ起動コマンドを記録する。

```toml
editor = "code --wait"
```

テンプレートのパスは固定レイアウトから導出するため、通常は設定ファイルにテンプレート一覧を重複して保持しない。

## エディタの決定方法

`--edit` 実行時は、以下の優先順位でエディタコマンドを決定する。

1. `config.toml` の `editor`
2. 環境変数 `VISUAL`
3. 環境変数 `EDITOR`
4. 見つからない場合はエラー

VS Code を使う場合は、`code` コマンドが PATH から起動できる状態で `editor = "code --wait"` を設定する。`--wait` により、テンプレートを保存してエディタを閉じるまで `tmrch` が待機する。

コマンド文字列の単純な空白分割は、引用符やパス中の空白を正しく扱えない。実装では「実行ファイル」と「引数」を構造化して設定するか、プラットフォームに応じて安全に解析する。利用者入力をシェルにそのまま渡す実装は避ける。

## テンプレート適用の詳細

- テンプレートはそのままファイルにコピーする。変数展開、日時置換、対話入力は初期版の対象外とする。
- テンプレート末尾の改行を含め、テンプレートファイルのバイト列を保持する。
- 1 つの拡張子につき 1 つのテンプレートを使う。
- `tar.gz` のような複合拡張子は初期版では `gz` として扱う。複合拡張子の優先一致は将来拡張とする。

## 終了ステータスとメッセージ

- 正常完了は `0`。
- 不正な引数、既存ファイル、設定・テンプレートの読み書き失敗、エディタ未設定・起動失敗は非 `0`。
- 通常結果（`--list` の一覧など）は標準出力、診断は標準エラーへ出力する。
- エラーには、対象のパスと利用者が取れる次の行動を含める。例: `editor が設定されていません。config.toml の editor、VISUAL、または EDITOR を設定してください。`

## 初期実装の範囲

1. `clap` で `tmrch <FILE>`、`tmrch --edit <EXTENSION>`、`tmrch --list` を定義する。
2. OS ごとの設定ディレクトリと `templates/` を必要時に作成する。
3. ファイル名から拡張子を安全に正規化し、テンプレートをコピーして新規作成する。
4. テンプレートファイルを既定エディタで開く。
5. テンプレートをソートして一覧表示する。
6. 少なくとも、テンプレートあり／なし、既存ファイルを上書きしないこと、`--edit` の新規作成、`--list` の空・複数件について自動テストする。

## 将来拡張（初期実装には含めない）

- `--editor <COMMAND>` または `tmrch config set editor ...` によるエディタ設定支援
- 名前ベース・複合拡張子ベースのテンプレート
- テンプレート変数（作成日時、ファイル名、プロジェクト名など）
- `--force` による明示的な上書き
- `--dry-run`、テンプレートの削除・複製・エクスポート
